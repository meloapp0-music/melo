# v1.5 release prep (build 34)

- Started: 2026-07-12
- Status: build prepped — awaiting device test on TestFlight, then App Store
- Last updated: 2026-07-12

## Context
Prompted by a real failure: the user's sisters attended Windy City Smokeout
and couldn't log it, because ALL the festival work sits in 7 commits AFTER the
v1.4 tag and was never in any shipped/TestFlight build. v1.4 (build 33) is in
App Store review and predates every festival fix. This preps a distinct new
version so it can be device-tested on TestFlight — the one verification step
that's never been done (everything so far was code-level: live-data sims,
adversarial review, unit tests).

## Version
- MARKETING_VERSION 1.4 → **1.5**; CURRENT_PROJECT_VERSION 33 → **34**.
- Chose 1.5 (feature release, not a patch) so it's unambiguously the next
  version and doesn't touch the in-review 1.4. TestFlight accepts it; when
  1.4 clears review, 1.5 is ready to submit.

## What's in 1.5 (everything after the v1.4 tag)
- Festival logging fixed end-to-end: strict year filter, edition isolation by
  curated venue (Grant Park, Empire Polo Club…), aftershow exclusion,
  direction filter (Attended=past / Wishlist=future), edition-window date span.
  [[festival-search-and-notification-deeplink]]
- Live festival autocomplete (any festival, not a curated list) + Select /
  Deselect all. [[festival-search-and-notification-deeplink]]
- Add a festival by its dates before the lineup drops (🎪 Whole event).
- Search an artist's whole upcoming tour. [[artist-tour-browser]]
- Going/Wishlist simplified to Search + Festival; genre autofill on add.
- Notification taps now deep-link (tour/genre alerts open the artist, not Home).
- Two adversarial review rounds on the festival resolver; all confirmed
  findings fixed or documented.

## Build steps done (2026-07-12)
- Verified working tree clean; VITE_JAMBASE_ENABLED=true (small-venue coverage on).
- `npm run build` (clean) → `npx cap sync ios` (clean).
- Version stamped 1.5 / build 34 (both Debug + Release configs).

## Remaining — the user does these
1. `npx cap open ios` → set device to "Any iOS Device" → Product → Archive.
2. Organizer → Distribute App → App Store Connect → Upload.
3. App Store Connect → TestFlight → wait for processing → install on device.
4. **Device test (the never-done step) — see checklist below.**
5. Only after it passes: submit 1.5 for App Store review (after 1.4 resolves).

## Device-test checklist (do this on TestFlight before shipping)
Signed in, on a real phone:
- Log a Show → Attended → Festival → type "Windy City Smokeout" → autocompletes?
  lineup loads with the RIGHT acts (not wrong-year/other-city junk)? multi-select
  → "Log N shows" saves? (the exact thing the sisters couldn't do)
- Same for "Coachella" and "Lollapalooza" — correct venue/lineup, no look-alikes.
- Wishlist → Festival → a festival before its lineup drops → "🎪 Whole event"
  with correct dates, adds to wishlist.
- My Shows → the logged festival shows as ONE card, tap to see the sets inside.
- Search an artist (Wishlist → Search) → their upcoming tour lists.
- General regression: log a normal single show, edit it, delete it — all fine.
